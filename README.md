# Kite Writer

한글(HWP/HWPX) 문서를 중심으로 Word·PDF·Markdown 문서까지 열어 편집하는 워드프로세서입니다. 윈도우 데스크톱 앱과 안드로이드 앱이 있습니다.
Electron + React + TypeScript + TipTap(ProseMirror) 기반이며, HWP/HWPX/DOCX 변환기는 외부 라이브러리 없이 직접 구현했습니다.

## 실행

```bash
npm install
npm run dev        # 개발 모드 (Vite + Electron)
npm run build      # 타입 검사 + 화면/메인 프로세스 빌드
npm start          # 빌드 결과 실행
npm run dist       # 버전 +1 후 Windows 설치 파일(release/) 만들기 (dist:same 은 버전 그대로)
npm run dev:web    # 브라우저에서만 실행 (파일은 내려받기로 저장)
```

## GitHub 릴리스

```bash
npm run release          # 패치 +1 → 커밋 → v<버전> 태그 → push
npm run release:minor    # 1.0.3 → 1.1.0
npm run release:major    # 1.1.0 → 2.0.0
```

태그가 올라가면 `.github/workflows/release.yml` 이 윈도우 실행기에서 설치 파일(`Kite Setup <버전>.exe`)과 스토어용 appx 를 만들어 GitHub 릴리스에 붙인다. 커밋하지 않은 변경이 있으면 멈춘다.

## 지원 형식

| 형식 | 열기 | 저장 | 비고 |
|---|---|---|---|
| HWPX | ✔ | ✔ | 글자/문단 모양, 표(셀 병합·배경·선 없음), 그림, 각주, 머리말/꼬리말, 쪽 번호, 하이퍼링크, 개요·문단 번호, 글상자, 그리기 개체(선·사각형·타원·호·다각형·곡선·묶음), 떠 있는 개체의 자리, 다단, 쪽 테두리/배경, 바탕쪽, 덧말·글자 겹침 |
| HWP 5.0 | ✔ | ✔ | 위와 같음. 암호/배포용 문서는 열 수 없음 |
| DOCX | ✔ | ✔ | 스타일 상속, 다단계 번호, 병합 셀, 필드, 각주, 탭 자리, 머리말/꼬리말(첫 쪽·짝수 쪽, 표·그림), 쪽 나눔 규칙 — 줄·쪽 자리를 Word 와 같게 (아래 'Word 문서를 Word 와 같게') |
| DOC | ✔ | – | Word 설치 시 서식 포함 변환, 없으면 LibreOffice → 텍스트 순으로 대체 |
| PDF | ✔ | ✔ | PDF에 든 글꼴로 그리고 줄바꿈·글자 위치를 원본과 같게 맞춤, 표·배경 상자·구분선·직인 재구성, 차트·도해는 원본 그림 그대로 / PDF로 저장(인쇄 품질) |
| Markdown | ✔ | ✔ | GFM 표, 각주(`[^1]`) |
| HTML / TXT | ✔ | ✔ | TXT는 UTF-8·EUC-KR 자동 판별 |

HWP·HWPX 저장 결과는 한글 2018에서 실제로 열어 확인했습니다 (`tests/hangul/` 참고).
다만 뒤에 더한 항목(그리기 개체·떠 있는 자리, 다단, 쪽 테두리/배경, 바탕쪽, 덧말·글자 겹침, 문단 테두리, 밑줄·취소선 종류 등)의 저장은
아직 한글에서 열어 확인하지 못했고, Kite 로 다시 읽어 같은 값이 나오는지만 시험했습니다 (`tests/test-shapes.mjs`, `test-columns.mjs`, `test-pagepaint.mjs`, `test-charshape.mjs`).

## 한글과 같은 주요 기능

- **쪽 단위 편집 화면**: 실제 용지 모양으로 쪽을 나눠 보여 줌 (문단 줄 단위·표 줄 단위로 다음 쪽으로 넘김), 각주는 해당 쪽 아래에 표시
- **편집 용지(F7)**: 용지 종류/방향, 위·아래·왼쪽·오른쪽·머리말·꼬리말·제본 여백 (한글과 같은 여백 의미)
- **글자 모양(Alt+L)**: 글꼴, 크기, 장평, 자간, 진하게/기울임/밑줄/취소선(선 종류·색, 글자 위 밑줄), 강조점, 글자 위치, 외곽선/그림자/양각/음각, 위·아래 첨자, 글자 색, 음영 색
- **문단 모양(Alt+T)**: 양쪽/왼쪽/가운데/오른쪽/배분 정렬, 왼쪽·오른쪽 여백, 들여쓰기/내어쓰기, 줄 간격(%, 고정 값), 문단 위·아래 간격, 문단 배경, 문단 테두리(변·선 종류·굵기·색·간격, 이어진 문단과 한 상자)
- **표**: 표 선택(왼쪽 위 ⊞ 손잡이 또는 F5 세 번 → 지우기/오려 두기/복사), 표 만들기(Ctrl+N,T), 줄/칸 추가·삭제, 셀 합치기(F5→M)/나누기(F5→S), 셀 테두리·배경·세로 정렬(F5→L), 셀 너비·높이 같게, 제목 줄, 열 너비 끌어 조절, 쉬운 계산식(가로·세로 합계/평균/곱: 천 단위 쉼표와 소수 자리를 따른다), 표를 문자열로·문자열을 표로
- **입력**: 그림(끌어 놓기·붙여넣기·크기 조절, 그림 자르기 대화 상자 또는 Shift+모서리 끌기), 도형(직선·화살표·사각형·둥근 사각형·타원), 글상자(Ctrl+N,B), 덧말 넣기, 글자 겹치기(㉮·⑩ 처럼), 하이퍼링크, 각주, 문자표(Ctrl+F10), 날짜/시간, 쪽 나누기(Ctrl+Enter), 단 나누기(Ctrl+Shift+Enter), 가로줄, 인용, 코드, 체크리스트
- **쪽**: 머리말/꼬리말(쪽 번호·전체 쪽수 필드), 쪽 번호 매기기(위치·모양·시작 번호), 다단 설정(단 수·간격·구분선, 한쪽이 좁은 두 단, 커서부터 새 다단으로 나누기), 쪽 테두리/배경(변마다 선·위치 기준·배경색, 첫 쪽 제외), 찾아가기(Alt+G)
- **서식 도구**: 스타일(F6), 글머리표/문단 번호 모양(가.나.다., ①②③, (1) 등), 모양 복사(Alt+C), 눈금자로 여백·들여쓰기 조절
- **편집**: 찾기(Ctrl+F)/찾아 바꾸기(Ctrl+H, 정규식·온전한 낱말), 되돌리기/다시 실행, 삽입/수정 모드(Insert), 문단 부호 보이기, 대문자/소문자 바꾸기, 문단 정렬(가나다순·역순)
- **파일**: 여러 문서 탭, 최근 문서, 자동 저장과 비정상 종료 복구, 미리 보기, 인쇄, PDF로 저장, 문서 정보(글자 수·원고지 매수)
- **화면**: 확대/축소(Ctrl+휠, 줄여서 쪽이 가로로 둘 들어가면 저절로 여러 쪽 보기 — 보기 → 축소하면 여러 쪽 보기로 끄고 켬), 폭 맞춤/쪽 맞춤, 전체 화면(F11), 투명 선 보이기, 어두운 테마(종이까지 어둡게 할 수 있음)
- **수식(Ctrl+N,M)**: LaTeX 또는 한글 수식 문법으로 쓰고 바로 그려 봄, 분수·근호·합·적분·행렬 틀과 기호판. HWP·HWPX의 수식을 수식으로 읽고, HWPX에는 한글 수식 개체로 저장
- **차례 만들기(입력 → 차례)**: 제목 1~3 스타일·한글의 개요 문단으로 "제목 ······· 쪽" 차례를 넣는다. 제목과 쪽 번호 사이는 오른쪽 맞춤 점선 채움 탭이라 제목을 고쳐도 쪽 번호가 오른쪽 끝에 맞는다. **차례 새로 고침**으로 제목·쪽을 다시 맞추고, **제목과 쪽 사이 점선 채우기**로 이미 써 둔 "제목 3"·"제목 ...... 3"·"제목⇥3" 문단을 점선 차례로 바꾼다 (HWP·HWPX 로 저장하면 한글의 점선 오른쪽 탭으로 남는다)

## 서식 문서 (Ctrl+Alt+N)

파일 → 서식 문서로 새로 만들기에서 미리 보기를 보며 고릅니다. 채워 넣을 자리는 옅은 노란 바탕으로 표시되고, 날짜는 오늘 날짜로 들어갑니다.

| 분류 | 서식 |
|---|---|
| 공문·행정 | 기안문(공문: 수신·제목·항목 체계·붙임·끝·발신 명의·결재·연락처) |
| 보고 | 개조식 보고서(□ ○ - 체계), 주간 업무 보고(가로), 출장 결과 보고서 |
| 회의·일정 | 회의록(논의·결정·실행 과제), 사업(행사) 추진 계획서(월별 일정표·예산) |
| 재무·구매 | 품의서(지출 결의, 결재란), 견적서(공급자 정보·품목·세액) |
| 인사·개인 | 휴가 신청서, 이력서 |
| 홍보·안내 | 보도자료, 안내문(공지) |

서식은 `src/templates/`에 코드로 들어 있어 HWPX·HWP·DOCX로 저장해도 표와 테두리가 유지됩니다 (`node tests/test-templates.mjs`).

## 검토·도우미 기능

- **명령 팔레트(Ctrl+Shift+P)**: 모든 명령을 이름(초성 검색 가능)으로 찾아 실행, 최근 사용 명령
- **맞춤법·공문서 검사(F8)**: 자주 틀리는 말, 띄어쓰기, 공문서 표기(날짜·시각·붙임), 순화어, 문장 부호를 밑줄로 보여 주고 한 번에 고침. AI 교정도 같은 창에서
- **변경 내용 추적(Ctrl+Shift+E)·메모(Ctrl+Alt+C)**: 넣은 글·지운 글을 사람별 색으로 표시하고 하나씩 또는 모두 받아들이기/되돌리기. 메모·답글·해결. DOCX와 주고받으며 그대로 유지(다른 형식은 반영한 글로 저장). 사용자 이름은 환경 설정에서
- **선택 영역 AI 고치기**: 글자를 고르면 뜨는 막대에서 다듬기·줄이기·공문서체·쉬운 말·번역·직접 지시. 결과는 'AI' 이름의 변경 제안으로 들어가 그 자리에서 받아들이거나 되돌림
- **AI 도우미** (Kite 창 안의 대화창, 세 가지 방식):
  - **계정 로그인**: Claude·ChatGPT·Gemini 의 공식 웹 대화창을 패널 안에 띄워 자기 계정(무료·구독)으로 쓴다. API 키가 필요 없고 한 번 로그인하면 유지된다.
    '선택 영역 보내기'·'문서 보내기'로 문서를 입력 칸에 붙이고, 웹 대화창에서 끌어 고른 답을 '고른 답을 문서에 넣기'·'선택 영역 바꾸기'로 문서에 넣는다.
    띄울 수 있는 주소·권한은 메인 프로세스가 정한다 (`electron/aiWeb.ts`: 전용 저장소, preload·Node 없음, 권한 거부, 로그인 창만 새 창 허용)
  - **API 키**: Claude·GPT·Gemini 와 바로 대화, 또는 **Ollama 로컬 모델**(키 없이, 문서가 이 컴퓨터 밖으로 나가지 않음). 설정(⚙)에서 Ollama 주소를 바꿀 수 있음.
    Claude 는 키를 넣지 않아도 Anthropic CLI 로 로그인해 둔 계정(`ant auth login`)이 있으면 그것으로 쓴다
  - **Claude 데스크톱**: 아래 AI 앱 연결(MCP)로 Claude 데스크톱이 문서를 직접 읽고 고친다
- **AI 앱 연결(MCP)**: 문서 읽기·개요·선택 영역·내용 넣기·블록 바꾸기·찾아 바꾸기·문단 스타일·표 넣기·메모 달기/답글·변경 목록/받아들이기·저장(항상 확인). "AI 앱의 수정을 변경 제안으로 남기기"를 켜면 AI가 고친 곳이 앱 이름의 변경 내용으로 표시됨
- **개인정보 찾기·가림**: 주민등록번호·전화·이메일·카드(Luhn 검사)·계좌(추정)·여권·운전면허 번호를 찾아 부분 또는 전체 가림. 변경 추적 중에도 원래 글을 남기지 않음
- **버전 기록(Ctrl+Alt+H)**: 저장할 때와 편집 중 5분마다 이 컴퓨터에 사본을 남기고, 이름 붙이기·지금과 비교(문단·낱말 단위)·되돌리기·새 탭으로 열기
- **실시간 공동 편집(실험)**: 같은 네트워크의 Kite끼리 접속 코드로 한 문서를 함께 고침. 상대 커서와 이름이 보이고, 되돌리기는 내가 고친 것만 되돌림

단축키 전체 목록은 프로그램의 **도구 → 단축키 목록(Shift+F1)** 에 있습니다.

## 안드로이드 앱

`android/` 는 데스크톱 앱과 같은 화면(`npm run build:web` 결과 `dist/`)을 WebView 로 띄우는 안드로이드 앱이다 (Android 8.0 이상). 형식 변환기·편집기는 모두 같은 코드를 쓰고, 안드로이드에서만 다른 부분은 `src/android.ts`(웹 쪽)와 `android/app/src/main/java/com/minary/kite/`(네이티브 쪽) 에 있다.

```bash
npm run android:apk       # 웹 빌드 → release/android/Kite-<버전>-debug.apk
npm run android:release   # 웹 빌드 → 서명한 release APK + Play 스토어용 AAB
```

필요: JDK 17 이상, Android SDK (`ANDROID_HOME` 또는 `android/local.properties` 의 `sdk.dir`). Android Studio 로 `android/` 폴더를 열어도 된다 (먼저 `npm run build:web`).
버전은 `package.json` 에서 가져온다 (1.2.3 → versionCode 10203).

release 서명: `android/keystore.properties` 에 `storeFile`, `storePassword`, `keyAlias`, `keyPassword` 를 적거나 환경 변수 `KITE_KEYSTORE_FILE`, `KITE_KEYSTORE_PASSWORD`, `KITE_KEY_ALIAS`, `KITE_KEY_PASSWORD` 를 준다. 없으면 서명하지 않은 APK 가 나온다.

GitHub Actions(`.github/workflows/android.yml`): 푸시할 때마다 debug APK 를 작업 결과물(artifact)로 올리고, `v*` 태그에서는 release APK·AAB 를 GitHub 릴리스에 붙인다. 서명하려면 저장소 Secrets 에 `ANDROID_KEYSTORE_BASE64`(jks 파일의 base64), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` 를 넣는다.

안드로이드에서는:

- 불러오기·저장은 시스템 파일 선택기(저장소 접근 프레임워크)를 쓴다. 저장한 문서는 같은 자리에 덮어쓰고 최근 문서에서 다시 열 수 있다. 다른 이름으로 저장할 때는 형식을 먼저 고른다
- 파일 관리자·메신저·메일의 '다음으로 열기'와 '공유'로 HWP·HWPX·DOCX·PDF·MD 등을 받아 연다. 파일 → 공유하기로 저장한 문서를 다른 앱에 보낸다
- 인쇄와 PDF로 저장은 안드로이드 인쇄 화면으로 한다 (PDF는 프린터에서 'PDF로 저장' 선택)
- 뒤로 가기는 열린 창·메뉴를 닫고, 없으면 저장 확인 후 끝낸다. 앱이 뒤로 가면 바로 자동 저장한다
- 휴대폰처럼 좁은 화면에서는 메뉴·도구 상자가 가로로 밀리고, 쪽 폭에 맞춰 연다
- DOC 열기, AI 도우미, AI 앱 연결(MCP), 공동 편집, 한컴오피스 글꼴 읽기는 데스크톱 앱 전용이다. 인터넷 권한이 없어 문서가 기기 밖으로 나가지 않는다

## Microsoft Store 배포

```
npm run dist:msix       # 맥·윈도우 어디서나 → release/Kite-<버전>-x64.msix (스토어 제출용, 서명 없음)
npm run dist:store      # 윈도우에서만: electron-builder 의 makeappx 로 → release/*.appx
```

`dist:msix` 는 `scripts/pack-msix.mjs` 가 윈도우 도구 없이 MSIX 규격(OPC 꾸러미, 64KB 블록 지도)대로 직접 묶는다. 스토어 제출 패키지는 Microsoft 가 서명하므로 서명하지 않는다. 직접 설치해 시험하려면 서명해야 한다.

제출 전에 채울 값:

- `package.json` → `build.appx` 의 식별 값은 Partner Center 값(minary.KiteWord, 게시자 minary)으로 넣어 두었다. `displayName` 은 Partner Center 에 예약한 앱 이름과 같아야 한다
- `src/appInfo.ts` → `CONTACT_FORM_ENDPOINT` 또는 `CONTACT_FORM_KEY`(문의 양식), `PRIVACY_URL`(아래 처리방침을 올린 웹 주소)
- `PRIVACY.md` 의 문의처. 이 내용을 웹에 올리고 그 주소를 Partner Center 의 개인정보 처리방침 칸에도 넣는다

스토어판에서 달라지는 점 (MSIX 로 설치되면 자동, 시험할 때는 `KITE_STORE=1`):

- 한컴오피스 전용 글꼴 읽기를 끈다 (한컴오피스용 글꼴의 라이선스 문제)
- Claude 데스크톱 등록은 설정 파일에 직접 쓰지 않고, 넣을 내용을 복사해 설정 파일을 열어 준다 (MSIX 의 AppData 쓰기 가상화)
- AI 앱이 Kite 를 실행할 때는 실행 별칭 `kite-word.exe` 를 쓴다 (`build/appx/extensions.xml`)

모든 판에 공통으로, 클라우드 AI 로 처음 보낼 때 동의를 받고, AI 응답마다 신고 단추가 있으며, 도구 메뉴에서 개인정보 처리방침과 오픈소스 라이선스(`npm run build` 때 `scripts/gen-notices.mjs` 가 만든다)를 볼 수 있다.

본 제품은 한글과컴퓨터의 한/글 문서 파일(.hwp) 공개 문서를 참고하여 개발하였습니다.

## 한글(HWP·HWPX)과 같은 모양으로 보이기

한글이 파일에 넣어 둔 첫 쪽 미리 보기 그림(PrvImage)을 기준으로 Kite 화면과 겹쳐 비교하며 맞췄다.

- 글꼴이 없을 때의 글자 폭: 문서의 글꼴이 이 컴퓨터에 없으면 한글·한자는 어느 한글 글꼴이든 글자 크기와 같은 폭(1em)이므로 그 폭으로 줄을 바꾼다 (`hwpMetrics`). macOS 의 기본 한글 글꼴(Apple SD Gothic Neo)은 0.865em 이라 그대로 두면 줄이 한글보다 일찍·늦게 바뀐다. 대체 글꼴은 나눔·애플 명조/고딕 순
- 칸 그러데이션 채우기(제목 띠 등), 떠 있는 표의 세로 위치(문단 기준 오프셋), 표 바깥 여백(위·아래)을 반영한다
- 한컴오피스 전용 글꼴(휴먼명조·HY 계열)이 없는 컴퓨터에서는 글자 모양은 다르지만 줄 바꿈·표 크기는 같다

HWP·HWPX 는 한글이 파일에 적어 둔 배치(줄마다의 세로 위치·줄 높이·기준선: HWPX 의 `hp:lineseg`, HWP 의 줄 정보 레코드)를 그대로 따른다.
한글로 만든 PDF 와 Kite 가 만든 PDF 를 쪽마다 견주어 맞췄다 (`tests/hangul/compare-run.mjs`, 줄 위치 차이는 `compare-diff.mjs`).

- 줄 상자: 줄 첫머리의 버팀대가 줄 높이와 기준선을 한글 값으로 만든다 (`hwpMetrics`, 문단 속성 `hwpVs`).
  한글이 줄 정보를 적지 않은 문단(HWP 의 일부 제목·글머리표 문단)은 같은 글꼴·크기·줄 간격의 다른 문단에서 줄 높이를 빌린다 (`hwpPitch`)
- 세로 위치: 본문 블록은 쪽 나누기가 한글의 쪽 안 자리(`hwpTop`)에 맞추고, 한글이 새 쪽에 놓은 줄·문단에서만 쪽을 넘긴다.
  셈한 배치와 실제 화면의 차이는 한 번 재서 보정한다. 문서를 고치면 고친 블록부터 그 쪽 끝까지는 자연 배치로 흐른다
  (블록 차례 `hwpSeq` 와 내용 크기 `hwpLen` 로 가린다)
- 떠 있는 개체(글자처럼 취급하지 않는 그림·글상자·도형)는 줄에 끼지 않고 한글이 놓은 자리(문단·쪽·종이 기준)에 뜬다.
  떠 있는 표는 글을 쪼개지 않고 한글이 놓은 차례(글을 밀어낸 표는 글 앞, 빈 문단 위에 덮인 표는 뒤)로 둔다
- 표: 칸 높이에는 테두리 두께가 들지 않는다. 줄 높이는 적힌 칸 높이와 '마지막 줄의 글자 아래 + 칸 위아래 안 여백' 가운데 큰 값이다
  (마지막 줄 아래 간격과 문단 아래 간격은 넣지 않는다 — 한글이 적어 둔 표 높이와 견주어 HWPX 표 239개 가운데 233개, HWP 표 21개 모두가 1.5px 안에서 맞았다).
  칸 안에 떠 있는 개체는 그 아래 끝까지 줄을 늘리고, 칸 안에서 표 하나뿐인 문단은 그 줄의 아래 간격을 표 아래에 둔다.
  합친 칸으로만 덮인 줄의 높이는 합친 칸 높이에서 거꾸로 셈하고, 내용이 넘치는 합친 칸은 마지막 줄을 늘린다.
  칸 대각선(여러 칸에 걸친 '셀 영역' 대각선 포함)을 그린다. 쪽에 걸쳐 칸이 나뉜 표는 한글처럼 아래를 선으로 닫고 조각마다 글 아래 자리를 지킨다
- 머리말·꼬리말은 글자 모양·정렬·표·그림과 영역 안 세로 맞춤까지 그대로 그린다. 홀수·짝수 쪽 머리말, 뒤 구역에서 시작하는 머리말·쪽 번호,
  '새 번호로 시작', 쪽 번호 위치 '없음'을 따른다. 감추기(표지·장 표지 쪽의 머리말·꼬리말·바탕쪽·쪽 테두리/배경·쪽 번호)는 그 문단이 놓인 쪽에서
  감춘다 (예전에는 첫 쪽 것만 따랐다). HWP·HWPX 에서 읽고 다시 저장한다
- 문단 여백: HWPX 에서 `hp:switch` 없이 바로 적힌 값(예전 방식)은 2배로 적혀 있으므로 반으로 읽는다. 문단의 줄 안 세로 정렬이 '가운데'일 때
  한글이 적는 기준선(줄 한가운데)은 글자 기준선으로 바꿔 쓴다. 돌린 그림은 돌려 그리고, 글자처럼 취급하는 표 앞의 빈칸만큼 표를 민다
- 인쇄·PDF: 쪽에 걸친 표 줄 안의 쪽 나눔 공간을 지우지 않고, 표의 위 바깥 여백을 이중으로 주지 않으며, 본문 폭에 꼭 맞는 표의 오른쪽 테두리를 자르지 않는다
- 그리기 개체: 선·사각형·타원·호·다각형·곡선·묶은 개체·글맵시를 한글의 변환 행렬(옮김 × (돌림 × 늘임)…) 그대로 SVG 로 그린다.
  선 종류·굵기·화살표, 단색·그러데이션(가운데에서 양 끝으로)·그림 채우기, 그림자, 도형 안의 글을 그리고, 자리는 '오프셋 + 바깥 여백'으로 잡는다 (`formats/shape.ts`)
- 쪽 테두리/배경(본문 기준·종이 기준, 채울 영역, 첫 쪽 제외)과 바탕쪽(양쪽·홀수·짝수)을 쪽마다 본문 뒤에 그린다
- 글자: 밑줄·취소선의 선 종류와 색, 글자 위 밑줄, 강조점, 글자 위치, 덧말, 글자 겹침. 문단: 테두리(이어진 문단을 한 상자로)
- 표: 안 여백을 따로 정하지 않은 칸은 표의 기본 안 여백을 쓰고, 빈 문단 하나뿐인 칸은 줄 높이만 차지한다. 이중선 테두리,
  쪽 경계에서의 나눔 방식(나눔 / 셀 단위로 나눔 / 나누지 않음)
- 다단: 단 정의(너비가 같은 단·다른 단, 구분선)를 읽고, 줄의 세로 위치가 되돌아가는 곳마다 다음 단(마지막 단이면 다음 쪽)으로 세어
  한글이 놓은 단과 자리에 그린다. 쪽 가운데에서 다단이 바뀌는 문서(다단 설정 나누기)와 단 나누기도 따른다.
  새로 쓰거나 고친 글은 Kite 가 단을 채운다: 넘치는 블록·줄을 다음 단으로 넘기고, 문단 안에서 단이 바뀌면 그 줄부터 다음 단 자리에 그린다 (`pagination.ts`)
- 글상자의 세로 맞춤(가운데·아래)은 한글처럼 안에 떠 있는 개체까지 넣은 내용 높이로 맞춘다
- 어울림으로 놓인 개체(문단 첫 글자 장식, 왼쪽에 놓인 그림 등) 옆의 줄은 한글이 적어 둔 가로 시작 자리만큼 들어가 시작한다
  (줄 정보의 가로 위치에는 문단 왼쪽 여백이 들어 있으므로 그만큼은 뺀다)
- 한 줄에 나란히 놓인 표와 글·그림(글자처럼 취급하는 표 + 빈칸 + 그래프 그림 등)은 한글처럼 표 옆 제자리에 놓는다. 표 뒤 내용은 한글이 적어 둔 줄(높이·기준선) 그대로
- 그림 보정·효과: 밝기·대비·회색조·흑백, 투명도, 그림 테두리 선, 그림자·네온·부드러운 가장자리·반사
- 문단 간격이 글자 단위(CHAR)로 적힌 HWPX: 값 1 = 7.5 HWPUNIT 으로 읽는다 (문단 아래 간격 80 → 6pt)
- 줄 번호(구역 설정): 본문 줄마다 왼쪽 여백에, 줄의 기준선에 맞춰 번호를 찍는다 (새로 시작·번호 간격·본문과의 거리·시작 번호). HWPX·DOCX 에서 읽고 쓰며,
  편집 용지 대화상자에서 켜고 끈다. 편집 화면·인쇄·PDF 모두
- 변경 추적: HWPX 의 넣은 글자·지운 글자를 한글처럼 밑줄·취소선(문서가 정한 사람 색, 기본 빨강)과 왼쪽 여백의 변경 막대로 그리고, HWPX 로 다시 저장한다
- 메모: HWPX 의 메모(쓴 사람·시각·내용)를 메모가 걸린 글과 함께 Kite 메모로 읽어 검토 창에서 본다 (인쇄에는 한글처럼 나오지 않는다)
- 양식 개체(명령 단추·선택 상자·라디오 단추·콤보 상자·입력 상자)는 한글(윈도 기본 모양)처럼 생긴 모양으로, 동영상은 첫 화면 그림과 재생 단추로,
  OLE 개체는 개체가 그려 둔 그림(원본 BMP, 표시 데이터의 DIB·WMF·EMF 안의 비트맵)으로 제자리에 그린다
- 한글이 배치하지 않은 파일(Kite 나 다른 프로그램이 쓴 HWP: 문단마다 세로 위치 0 인 줄 하나)의 줄 정보는 따르지 않고 Kite 가 배치를 셈한다

## Word 문서를 Word 와 같게

DOCX 는 Word 가 그리는 규칙대로 줄 높이·자리·쪽 나눔을 셈한다. 이 저장소를 만든 환경에는 Word 가 없어, 같은 문서를 LibreOffice 로 PDF 로 바꾼 것을 기준으로
글줄마다의 쪽·가로·세로 자리를 견주며 맞췄다 (Apache POI 의 시험 문서 111개: 쪽 수가 같은 문서 101개, 앞 두 쪽에서 같은 쪽에 놓인 줄 74%, 맞은 줄의 세로 차이 중앙값 1px).
Word 자체와 견준 것은 아니므로 Word 와 LibreOffice 가 다르게 그리는 곳은 LibreOffice 쪽을 따랐을 수 있다.

- 줄 간격: '1줄'은 글꼴의 고유 줄 높이(글꼴마다 다르다)의 배수, '고정'·'최소', 줄 격자(docGrid). 영문 글꼴과 한글 글꼴을 따로 물려받고 테마 글꼴을 따른다
- 문단 사이 간격: 앞 문단의 아래 간격과 뒤 문단의 위 간격 가운데 큰 쪽만 둔다 (간격을 더하는 호환 설정이 있는 문서는 더한다). 같은 스타일 사이 간격 없음(contextualSpacing)
- 번호 매기기: 수준별 번호 글(`%1.%2.`), 글머리표, 시작 번호·수준 덮어쓰기, 수준의 들여쓰기와 탭. 번호는 문단 앞의 글자로 넣는다
- 탭: 문단·스타일의 탭 자리(왼쪽·가운데·오른쪽·소수점, 채움)와 기본 탭 간격, 절대 위치 탭. 탭 폭은 화면에서 재서 탭 자리에 맞춘다 (`src/editor/tabLayout.ts`)
- 표: 칸 안 여백(스타일→표→줄→칸), 표의 가로 자리(호환 모드에 따라 다르다), 표 스타일의 문단·글자 모양
- 머리말/꼬리말: 글꼴·탭·표·그림을 그대로 그린다. 첫 쪽을 다르게, 짝수 쪽을 다르게. 여백보다 긴 머리말·꼬리말은 Word 처럼 본문 영역을 줄이고, 첫 쪽만 다르면 첫 쪽의 본문 영역만 따로 잡는다
- 쪽 나눔: 외톨이줄 방지(쪽 끝·쪽 처음에 문단의 한 줄만 두지 않는다. Word 기본), 다음 문단과 함께(제목), 문단을 나누지 않음
- 떠 있는 개체(DrawingML): 그림·도형·글상자·묶음을 종이·여백·단·문단 기준 자리(오프셋·맞춤·백분율)와 쪽·여백에 대한 상대 크기로 놓는다.
  글이 든 사각형·타원은 고칠 수 있는 글상자로, 그 밖의 기본 도형(별·화살표·다각형 등)은 돌림·뒤집기·테마 색·선 스타일까지 그린 도형으로. 머리말·꼬리말 안의 떠 있는 개체도 그린다
- 둘레 글 흐름: 정사각형·빽빽하게·통과 배치는 개체 옆으로, 위아래 배치는 개체 아래로 글이 비켜 간다 (뒤 문단까지. 인쇄·PDF 도 같다)
- 쪽 배경(색·바둑판 그림, Word 처럼 '배경 표시' 설정이 있을 때)과 선으로 된 쪽 테두리 (`node tests/test-docx-drawing.mjs`)
- DOCX 로 저장할 때도 위 내용(탭 자리, 쪽 나눔 규칙, 머리말/꼬리말의 모양과 첫 쪽·짝수 쪽)을 쓴다. Kite 가 쓴 DOCX 를 LibreOffice 로 열어 원본과 줄 자리가 같은지 확인했다 (`node tests/test-docx-layout.mjs`)

## PDF 를 원본과 같게

PDF 는 편집할 수 있는 문서로 다시 짜서 연다(글줄·표·상자·그림). 이 저장소를 만든 환경에는 Acrobat 이 없어, 같은 PDF 를 poppler 로 그린 쪽을 기준으로
글줄 자리와 쪽 그림을 견주며 맞췄다 (LibreOffice 가 만든 PDF 55개와 Kite 가 한글 문서에서 만든 PDF 11개: 쪽 수는 모두 같고, 맞은 줄의 세로 차이 중앙값 1.3px).

- 줄 자리: 문단 간격으로 적지 못한 작은 간격·반올림 오차를 다음 간격에 넘겨, 줄이 내려갈수록 위로 올라가던 누적 오차를 없앴다. 본문이 짧은 쪽의 꼬리말처럼 큰 간격도 그대로 둔다
- 차트·도해: 사선·곡선·막대(채운 사각형)가 모인 곳은 쪽 그림에서 그대로 잘라 그림 한 장으로 넣는다 (눈금 글자·범례 포함. 그 안의 글자는 고칠 수 없다)
- 표의 칸 안에 있는 체크 상자·입력란의 괄호 선처럼 표·밑줄·구분선이 아닌 선 조각은 칸 배경의 제자리에 그린다
- 아주 조금 기운 긴 선은 곧은 선(단 구분선)으로 다룬다. 뒤에 칠한 흰 사각형에 덮인 글자는 뺀다

## 알려진 제한

- PDF: 아직 원본과 다르게 보일 수 있는 것 — 표의 이중선·일부 상자 테두리(한 줄로 그리거나 빠진다), 윤곽선·그러데이션으로 그린 글자(워드아트),
  칠한 도형 안의 글(바탕색이 빠질 수 있다), 표 밖에 있는 체크 상자·짧은 선, 글 옆 그림 앞에 다른 글자가 끼어 있는 배치(그림이 글 아래로 내려간다).
  쪽 맨 아래의 숫자만 있는 줄은 쪽 번호로 보아 쪽 번호 설정으로 옮긴다.

- Word 문서: 아직 Word 와 다르게 보이는 것 — 둘레 글 흐름은 한쪽으로만(양쪽 배치는 남는 자리가 넓은 쪽으로) 사각형 둘레로 흐르고(빽빽하게의 꼴 선은 쓰지 않는다),
  종이·여백 기준으로 놓인 개체와 머리말 안 개체 둘레로는 글이 비켜 가지 않는다. 글상자 안 글이 상자 꼴(타원 등)을 따라 흐르지 않고, 그림 쪽 테두리(장식 그림)는 빠진다.
  틀(framePr: 예전 방식의 쪽 번호 틀 등)과 떠 있는 표, 차트(자리 표시 그림), 오른쪽에서 왼쪽으로 쓰는 글, 작은 대문자, 문서 중간에서 바뀌는 구역의 용지·머리말(끝 구역의 것만 쓴다), 여러 쪽에 걸친 표의 줄 나눔 자리.
  번호 매기기는 글자로 바뀌므로 Kite 에서 항목을 더해도 번호가 저절로 이어지지 않고, DOCX 로 다시 저장하면 번호가 보통 글자로 남는다.
  첫 쪽만의 본문 영역과 탭 자리는 HWP·HWPX 로 저장되지 않는다 (탭은 화면에서 잰 폭으로 저장된다).
  떠 있는 개체의 자리·둘레 글 흐름은 HWPX·HWP 로는 저장되지만(어울림·자리 차지), DOCX 로 다시 저장하면 떠 있는 그림은 글줄 안 그림으로, 글상자는 안의 문단으로 풀리고
  도형은 빠진다. 쪽 배경·쪽 테두리도 DOCX 로는 저장되지 않는다.

- AI 도우미의 '계정 로그인' 방식은 각 회사의 웹사이트를 그대로 띄우는 것이라, 그 사이트가 내장 창에서의 로그인을 막으면(Google 계정 로그인 등) 쓸 수 없습니다. 그럴 때는 이메일 로그인이나 API 키 방식을 쓰세요.
  이 방식은 시험용 로컬 페이지로만 동작을 확인했고(붙이기·답 넣기·권한 차단), 실제 claude.ai·chatgpt.com·gemini.google.com 로그인은 확인하지 못했습니다.

- 그리기 개체: 글맵시는 모양대로 휘지 않고 틀에 맞춰 늘인 글자로 그립니다. 묶거나 돌린 도형 안의 글은 화면에서 고칠 수 없습니다.
  도형은 그림처럼 크기·모양을 끌어 고치는 편집 기능이 없습니다 (넣기와 지우기만).
- 양식 개체는 모양만 그리며 누르거나 고를 수 없고, 저장하면 도형이 됩니다. 동영상은 첫 화면 그림으로 저장됩니다.
  OLE 개체는 비트맵으로 그려 둔 모양만 꺼내고, 선으로 그린 메타파일(WMF·EMF)은 자리 표시로 둡니다.
- 그림 효과: 밝기·대비·회색조·흑백·투명도는 HWPX 로 저장하지만, 그림자·네온·부드러운 가장자리·반사는 화면에만 그리고 저장하지 않습니다.
- 한 줄에 나란히 놓인 표와 글·그림은 저장하면 표 옆 내용이 글상자에 담깁니다 (한글에서 한 문단으로 되돌리지 않습니다).
- HWP(바이너리) 문서의 줄 번호와 변경 추적은 읽지 않습니다 (표본 문서가 없어 저장 위치를 확인하지 못했습니다).
- 쪽 테두리/배경을 양쪽·짝수 쪽·홀수 쪽에 서로 다르게 정한 문서는 '양쪽' 것만 그립니다.
- 저장: 도형과 떠 있는 자리는 HWPX·HWP 로 저장되지만, HWP(바이너리)로는 글상자가 풀려 안의 글만 남고 글맵시·짝수/홀수 바탕쪽은 저장되지 않습니다. 그러데이션 쪽 배경은 HWPX·HWP 어느 쪽으로도 저장되지 않고, DOCX 로는 도형이 빠집니다. 칸 대각선·홀짝 머리말은 화면 전용입니다.
- 다단: 표는 단에 걸쳐 나누지 못해 통째로 다음 단으로 넘기고, 단보다 긴 표는 그 단에서 쪽으로만 나눕니다. 앞 다단의 단 높이를 고르게 맞추지(배분 다단) 않고, 각주는 단이 아니라 쪽 아래에 모읍니다.
  너비가 다른 단에 걸친 문단은 시작한 단의 폭으로 줄을 바꿉니다. 다단 문서는 고칠 때마다 전체를 다시 배치하므로 아주 긴 문서에서는 느릴 수 있습니다. DOCX 로는 구역의 다단과 단 나누기만 주고받습니다.
- 바탕쪽은 읽어서 그리고 다시 저장할 뿐, 고치는 화면은 없습니다.
- 미주는 각주처럼 그 쪽 아래에 이어진 번호로 모입니다 (한글처럼 문서 끝에 따로 모으지 않습니다). 각주·미주 번호의 앞뒤 장식 문자는 'N)' 모양으로만 씁니다.
- 아주 큰 문서(최상위 블록 십만 개 넘게, 1만 쪽 넘게)는 여는 데 1분쯤 걸립니다 (1만 6천 쪽 시험 문서: 문서 들어옴 10초, 쪽 나눔 36초).
- 한글 배치 따르기는 한글이 저장한 줄 정보가 있는 문서에만 적용됩니다 (한글이 아닌 프로그램이 만든 문서는 Kite 가 배치를 셈합니다).
- 수식: 한글 수식 문법은 자주 쓰는 범위만 변환합니다. DOCX·HWP·ODT 등에는 한글 수식 문법 글자로 저장됩니다. HWPX에 쓴 수식의 크기는 어림값이며 한글이 열 때 다시 계산합니다.
- 변경 내용은 DOCX·HWPX, 메모는 DOCX 에서 그대로 주고받습니다 (HWPX 의 메모는 읽기만 합니다). HWP·PDF 등으로 저장하면 변경을 반영한 글만 남고, DOCX 가 아니면 메모는 빠집니다 (저장할 때 묻습니다).
- 실시간 공동 편집은 실험 기능입니다. 본문만 함께 고쳐지고 메모 내용·쪽 설정 변경은 나누지 않으며, 파일 저장은 연 사람이 합니다.
- 쪽 나누기는 화면 배치 기준이라 한글과 쪽 수가 조금 다를 수 있습니다 (HWP·HWPX 는 한글의 쪽 배치를 따릅니다. 여러 쪽에 걸친 표의 줄 나눔은 Kite 가 셈합니다).
- 표의 한 줄이 한 쪽보다 길면 그 줄은 나누어지지 않습니다.
- PDF 불러오기: 원본과 같은 모양을 위해 줄마다 강제 줄 나눔을 넣고 낱말 위치를 자간으로 맞추므로, 문단 중간을 고치면 줄이 원본처럼 다시 흐르지 않습니다. 분수·첨자 같은 수식과 글자를 도형으로 그린 부분은 원본과 다르게 보일 수 있습니다. PDF에 든 글꼴과 표에 걸친 그림(직인 등)은 Kite 안에서만 쓰이고 HWP/HWPX/DOCX로 저장하면 시스템 글꼴로 바뀝니다.
